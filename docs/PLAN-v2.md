# WLAN Scan v2 plan

Written 2026-11-13 from a code review of `main` at `13492ed`. Two parts: **remediations**
(bugs and cleanup found in the review) and one **feature**: floor plan upload with a survey
mode that produces a signal heatmap.

Work on branch `v2`. Never push to `main` and never push a `wlan-scan-v*` tag: a tag starts
the public release workflow. Bryan merges and tags.

## Ground rules for whoever builds this

- The dev-server is Linux with no Wi-Fi adapter, and the app's scanners are Windows (wlanapi,
  PowerShell, netsh) and macOS (CoreWLAN). So **Phase 0 comes first**: a replay backend and
  headless tests let everything else be built and checked here.
- Platform code you can't run (ctypes wlanapi, CoreWLAN) is changed behind tests that use
  recorded fixtures. List every such change under "Needs Bryan's hardware" in
  `docs/V2-STATUS.md` so he can check it on a real Windows/Mac machine.
- One commit per numbered item, message prefixed with its number (`R3: ...`). Keep
  `docs/V2-STATUS.md` current: done / in progress / blocked, with the reason.
- Run tests headless: `QT_QPA_PLATFORM=offscreen python -m pytest -q`.

## Phase 0: make it buildable and testable on Linux

**P0.1 Scanner backend interface.** One `ScannerBackend` protocol (`open`, `close`, `scan() ->
ScanResult`, `capability()`, `name`) plus a picker. Replace the `use_mac` / `use_pwsh` /
`use_netsh` if-chain in `gui/main_window.py` `ScannerWorker.run` with: pick a backend, fall
back down an ordered list, and report which one is active.

**P0.2 Record and replay.** `--record FILE` writes every `ScanResult` as JSON lines (BSS
fields + `ies_raw` as hex + timestamp). A `ReplayBackend` (`--replay FILE`, also selectable on
Linux) plays them back at the scan interval. Commit 2–3 small fixture recordings under
`tests/fixtures/` (hand-built or synthetic is fine; mark synthetic ones). Survey mode is
developed against this.

**P0.3 Tests and CI.** `requirements-dev.txt` (pytest, pytest-qt). Add CI on push and pull
request that runs the tests (Linux, offscreen). Leave the tag-only build/release jobs as they
are.

## Phase 1: remediations

**R1 IE parser is wrong for Wi-Fi 6/7 and channel width** (`ie_parser.py`).
- Element 255 is the Extension element: the extension ID is the *first byte of the body*,
  not a nested TLV. The current loop reads `body[0]`/`body[1]` as id/len, so HE detection
  is luck and EHT (ext 108) is looked for under element 127 (Extended Capabilities) instead.
- Width comes from *capabilities* (VHT caps always set 80+, HE caps set 80 even on 2.4 GHz),
  so the channel map draws 2.4 GHz HE networks 80 MHz wide. Derive width from the
  *operation* elements: HT Operation (61), VHT Operation (192), HE Operation (ext 36, incl.
  6 GHz operation info), EHT Operation (ext 106, 320 MHz). Clamp by band.
- Record the operating centre/primary channel for 40/80/160 so the channel map can place the
  block correctly.

**R2 Security parsing.** `_parse_rsn` indexes `body[6..7]` and the AKM count without bounds
checks, so a short RSN IE raises. FT-PSK, PSK-SHA256 and FT-802.1X are not labelled WPA2.
PSK+SAE (transition mode) shows as WPA3 only; label "WPA2/WPA3". Suite-B → "WPA3-Enterprise",
OWE → "OWE (Enhanced Open)". Parse RSN Capabilities for PMF (MFPC/MFPR; README claims it).
Parse the WPA1 vendor IE (221, 00:50:F2:01) and the capability Privacy bit for WEP.

**R3 One IE parser.** `pwsh_scanner.py` has its own `_parse_ie_hex` / `_parse_rsn_ie`. Make
it call `ie_parser.parse_information_elements` so ARM64 Windows gets the same results.

**R4 Max rate.** It's taken from legacy rate sets (54 Mbps max), and CoreWLAN uses a guess.
Either compute a real PHY max from HT/VHT/HE MCS maps, NSS and width, or drop the column and
the CSV field. Prefer computing it for the ctypes/pwsh paths and blank where unknown.

**R5 One vendor lookup, no network on the scan path.** There are two:
- `vendor_lookup.py` (IEEE list downloaded into SQLite at `~/.wlan_scan`): the first scan
  blocks up to 30 s on the download; when the download fails `_init_cache` recurses until
  `RecursionError` and retries on every lookup; one SQLite connection is shared by the
  scanner and neighbor-dialog threads (`check_same_thread` error).
- `oui_lookup.py` (3,000-line hand dict + `api.macvendors.com` with a 1 s timeout per
  unknown OUI, called on the scan thread; cache written next to the package, read-only in a
  frozen build; sends BSSIDs to a third party).
Replace both with one module: a bundled IEEE OUI snapshot (generated by a script at build
time, shipped as a compact file), thread-safe lookups, an optional background refresh. Flag
locally administered (randomized) MACs as "Randomized" instead of an unknown vendor.

**R6 Scan timing.** `WiFiScanner.get_scan_results` sleeps 2 s after `WlanScan` plus a
cooldown, so the 0.25/0.5/1 s intervals never happen. Use `WlanRegisterNotification` for
`wlan_notification_acm_scan_complete` (timeout fallback), separate "trigger a scan" from
"read the cached BSS list", and show the real scan rate in the status bar. Survey mode needs
predictable sample timing.

**R7 Don't block the GUI thread.** `_connected_bssid` runs `netsh` (10 s timeout) from the GUI
thread every 10 s; `_detect_gateway` runs `route print` on click. Move both into the worker
or a small background task.

**R8 Start/stop and auto-scan.** Stop waits 2 s but a scan can take longer, and `start()` on a
still-running QThread does nothing, so Stop → Scan can leave the button saying Stop with no
scans. Unchecking Auto-scan does nothing; `pause`/`resume` are unused. Make stop
interruptible (event, not sleep loop), make the button reflect real state, and either wire
Auto-scan to pause/resume or remove it.

**R9 macOS correctness.**
- "Running on non-Windows platform — scanner is unavailable" shows on macOS too; it should
  only show when no backend is available.
- Logs say "Using macOS airport CLI scanner" when CoreWLAN is used.
- `airport` was removed in macOS 14.4; keep the fallback only where it exists and say so.
- Without Location Services permission CoreWLAN returns nil SSID/BSSID and every entry is
  silently skipped. Detect it and tell the user how to grant permission (`NSLocationUsage`
  key in the app bundle's Info.plist, see `wlan-scan-mac.spec`).
- Log directory on macOS should be `~/Library/Logs/WLANScan`.

**R10 CSV export.** The success message says "Exported N scans" but only the last scan is
written. Fix the message; keep CLI and GUI export on one shared writer.

**R11 Versioning and updates.** `__init__.__version__ = "0.1.0"`, `version.py` holds a SHA,
and the updater compares the build SHA against `main`'s HEAD commit, so any commit (a README
edit) shows "Update available" pointing at a release that may be older. Use one version
source (from the tag at build time), check the latest *release* via the releases API, and
compare versions.

**R12 Logging and cleanup.** Logger is named `wifiexplorer` with files `wifiexplorer-*.log`
that are never pruned; rename and keep ~14 days. `pwsh_scanner` prints debug to stderr;
route it to the logger. Remove dead code (unused `band` assignments, unused imports,
`pause`/`resume` if R8 drops them). Keep the netsh fallback but mark its values as estimates
(RSSI is converted from a percent).

**R13 Tests.** Add fixture tests for: `ie_parser` (real IE blobs for 11n/ac/ax/be on 2.4, 5 and 6
GHz, WPA2/WPA3/transition/OWE/Enterprise, truncated IEs), `freq_to_channel` including 6 GHz
and channel 14, netsh text parsing (English sample output), pwsh JSON mapping, vendor lookup,
CSV writer.

## Phase 2: floor plan upload and survey mode (feature request)

Bryan, 2026-11-13: load a site's floor plan, capture signal strength and other wireless data at
specific points on it, so a walk-through produces a mapped survey instead of a list of
readings.

**F1 Survey project file.** `.wlansurvey` = a zip with `project.json` (name, site, created,
floors, scale, settings), the floor plan image(s), and `samples.jsonl`. Save, Save As, Open,
autosave every minute to a sidecar. Versioned schema.

**F2 Floor plan import.** PNG/JPG, and PDF page 1 via QtPdf (pick a page if there are several).
Multiple floors per project, each with its own image, scale and samples.

**F3 Scale calibration.** Click two points on the plan and type the real distance (ft or m, ft
default). Until calibrated, everything works in pixels and the UI says so.

**F4 Survey tab.** A new main tab with a `QGraphicsView` of the plan (pan, zoom, fit).
- **Point mode (build first):** click where you're standing. The app takes N scans
  (default 3, setting) and stores per BSS: SSID, BSSID, RSSI, channel, width, band, security,
  utilization, station count, plus connected BSSID and timestamp. Show a progress ring on
  the point; the point gets a colour for the chosen metric. Undo last point; delete or retake
  a point from its context menu.
- **Walk mode (after point mode works):** click a start point, walk, click the next point;
  samples taken in between are spread along the segment by timestamp.
- Optional per point: ping to the gateway (avg/loss over 5 pings), using the existing ping
  code.

**F5 Heatmap.** Layer over the plan, recomputed when the metric or filter changes:
- Metric: best RSSI (any of selected SSIDs), RSSI of one BSSID, number of APs ≥ -67 dBm
  (coverage overlap), co-channel count on the strongest AP's channel, channel utilization.
- Filter: SSID(s), band.
- Interpolation: inverse-distance weighting on a grid clipped to a drawn survey boundary
  (default: convex hull of the points + a margin). Keep it numpy-only if possible; add numpy
  to requirements if needed.
- Colour scale with labelled thresholds (default -67 voice / -70 data / -80 edge), legend,
  opacity slider, toggle point labels.

**F6 APs on the plan.** Estimate each BSSID's location as the RSSI-weighted centroid of its
strongest points; show markers that can be dragged to the real spot or added by hand, labelled
with name/BSSIDs (group BSSIDs of one radio by MAC proximity).

**F7 Export.** PNG of the current heatmap with legend and title; CSV of all samples (one row
per point × BSS, with x/y in feet); optional PDF report (one page per floor/metric) via
QtPrintSupport.

**F8 Tests and a demo.** Unit tests for the project file round-trip, calibration maths, IDW
grid, walk-mode interpolation. A synthetic survey fixture (plan image + samples) and an
offscreen render test that saves a heatmap PNG to `docs/` for the README.
